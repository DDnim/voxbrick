# 作品文件格式（format 1）

一件作品是 `works/<id>.json` 一个文件：一个体素模型加上标题、作者、许可这些元数据。
页面和拼砖程序只读这个文件，零件的排法、零件清单和拼装步骤都是从它算出来的。
编辑器可以用 [`schema/work.schema.json`](../schema/work.schema.json) 做补全和检查。

## 例子

```json
{
  "format": 1,
  "id": "tiny-tower",
  "title": "小塔",
  "description": "三层的小塔，红色塔顶。",
  "author": { "name": "你的名字", "url": "https://example.com" },
  "license": "CC-BY-4.0",
  "unit": "brick",
  "palette": { "R": "red", "W": "white" },
  "sections": [
    { "from": 0, "to": 1, "name": "塔身" },
    { "from": 2, "to": 2, "name": "塔顶" }
  ],
  "layers": [
    ["WW", "WW"],
    ["WW", "WW"],
    [".R", "R."]
  ]
}
```

## 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `format` | ✓ | 固定是 `1` |
| `id` | ✓ | 小写字母、数字和 `-`，和文件名一致 |
| `title` / `description` | ✓ | 页面上显示的标题和介绍 |
| `author` | ✓ | `{ "name": "...", "url": "..." }`，url 可省略 |
| `license` | ✓ | `CC0-1.0` / `CC-BY-4.0` / `CC-BY-SA-4.0` 之一 |
| `unit` | ✓ | `brick`：1 层 = 1 块砖高（9.6mm）。`plate`：1 层 = 1 块薄板高（3.2mm），竖向精度是砖的 3 倍，适合画五官 |
| `seed` |  | 拼砖程序的随机种子，默认 `1`。测试说“没有连成一整块”时，先换几个 seed 试试 |
| `palette` | ✓ | 一个字符 → 颜色 id。颜色 id 见 [`src/core/catalog.js`](../src/core/catalog.js) 的 `COLORS` |
| `sections` |  | 拼装步骤标题里显示的部位名，`from`/`to` 是层号（含两端） |
| `i18n` |  | 翻译，比如 `{ "en": { "title": "...", "description": "...", "sections": ["..."] } }`。`sections` 按顺序对应上面的部位名。页面切到英文时显示这里的内容，缺的字段显示原文 |
| `layers` | ✓ | 模型本体，见下面 |

## layers：怎么读

`layers[y][z]` 是一行字符串，其中第 `x` 个字符是格子 `(x, y, z)`：

- `y`：层，`0` 是最底层（放在桌面上那层），往上递增。
- `z`：行，从**后**往**前**。每层的最后一行是作品的**正面**（脸朝的那边）。
- `x`：字符，面对作品时从左往右。
- `.` 是空格；其他字符在 `palette` 里查颜色。

每层的行数相同，每行的字符数相同。占地最大 64×64 格，高度不限。
1 格 = 1 个凸点间距（8mm）宽，高度看 `unit`。

## 怎样的模型拼得出来

测试会检查每件作品，下面几条不满足就过不了：

- **连成一整块**：上下相邻两层只要俯视有重叠就能扣在一起。只靠左右挨着的部分（比如手臂只在侧面贴着身体）要在同一层里有同色的格子把它和身体连起来。
- **悬空的格子要够得着支撑**：下面是空的格子（帽檐、伸出的手），同一层要有一块零件能同时盖住它和一格有东西托着的格子。一圈斜着往外伸得太多时会排不出来，把外沿收小一点，或者让下一层先往外扩一点。
- **站得稳**：整体的重心要落在最底层的范围内。几个分开的角色可以放在一块两层的底板上连起来。

## 看不见的格子

六个方向都被别的格子挡住的格子在外面看不见，程序会把它当作“什么颜色都行”，用来拼更大的零件。
所以内部的颜色随便填，写成和外面一样的颜色就好。
